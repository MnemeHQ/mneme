enforcement may be claimed only after R3 §8.D scoring passes. It does not
pin the R3 baseline (§6.1: that belongs to the pre-scoring completion
record). It does not by itself authorize unblinding. G2-1 remains **FAIL**.

## 6. Anomalies and differences (reported as found)

No run failed or was voided. All observations that differ from the plan or from #646:

### 6.1 Fixture authoring error before any run

The first `mneme adr import` rejected the newly written ADR-951 with
`invalid priority 'high'`. The front matter was corrected to `priority: normal`
and re-imported before the fixture commit and before any run. The system under
test was not changed.

### 6.2 Dependency freeze digest differs from the candidate R3 freeze

This venv's `pip freeze` SHA-256 (`60dddbca…3feca`) differs from the R3
pre-registration §2 candidate (`253e5bc8…00c2`). Diffing the two, excluding
the `mneme-hq @ file:///…` line whose local path differs, shows that the
candidate environment also contains build tooling: `build==1.6.1`,
`colorama==0.4.6`, `packaging==26.3`, `pyproject_hooks==1.3.3`. This
runtime-only venv lacks those. Every package present in both has the same
version. The wheel hash is identical.

### 6.3 Envelope key set: `scratchpad_dir` absent on 2.1.312

On 2.1.312, every `Write` envelope (10/10) has the top-level keys `cwd`,
`effort`, `hook_event_name`, `permission_mode`, `prompt_id`, `session_id`,
`tool_input`, `tool_name`, `tool_use_id`, `transcript_path`. `tool_input`
holds `content`, `file_path`. Compared with #646 (2.1.310), `scratchpad_dir`
is **absent** and nothing was added. The identifier keys (`*_id`) are
unchanged.

### 6.4 Warn-mode deferral stops the headless host before the write

This is unchanged from #646 §6.2. r3a/r3b: the hook exited 0 with
`hookSpecificOutput.permissionDecision = "defer"` (exactly one such decision
per run in the debug log, none in any other run) and wrote a `deferred` record.
`claude -p` on 2.1.312 then ended with `stop_reason: "tool_deferred"`. It emitted
no tool result and did not execute the `Write`, so the target stayed absent.
This must not be described as "warn mode lets the write proceed". The
interactive host was not tested.

### 6.5 Baseline wheel digest differs from #646's

The baseline wheel built here from `f8591102` (`8d788ece…7d30`) is not
byte-identical to #646's (`6dfa470e…fabd6`). The wheel build is not
byte-reproducible across sessions. This affects only the §5.2 replay aid,
not any pin.

### 6.6 Harness notes

- `MNEME_SESSION_STATE_DIR` was set per run, unlike #646, so session snapshots did
  not land in the shared `%TEMP%`. The parent Claude Code session's `CLAUDE*`
  environment variables were unset for each child run. The child used the
  account's default config directory (`%USERPROFILE%\.claude`, with no
  `CLAUDE_CONFIG_DIR`). That is **not** scorer B's configuration.
- The analysis script's first-pass `defer` flag matched an unrelated host debug
  line ("deferred tools"). Deferral was therefore established from the hook's
  `returned permissionDecision` lines instead (§6.4). The flag played no part
  in any result.

AT-class (non-numeric attribution) behavior was not characterized here. R1 §3
