**Attempt 0, script defect.** The pre-block `ls-remote` check passed a
quoted `PATH` to bash through Windows PowerShell 5.1. That version drops
embedded double quotes from native arguments, so `PATH` split at
`Program Files` and the check exited 127. The script read this as "fixture
unreachable" and aborted, as designed:
- no probe ran and no rule was added;

The dry test simulated this check, so it could not catch the defect. Fix:
the check is written as a separate LF bash file. Reproduced, fixed and tested
live (read-only) before re-authorization.

The same quoting appears in the classifier call of every C3 operator script
(here and in #620, #622, #629, #632). There it is harmless, because the
pinned interpreter path and the model name contain no spaces. It is
disclosed and unchanged.

## 2. The D-4 harness defect and fix (#636)

**What happened.** Run 1 stopped correctly at D-4-Write-1:
- D-4 put `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY=http://127.0.0.1:9` in the
  project settings `env`.
- Claude Code applies that `env` to **itself**, so its API calls were
  refused: 10 retries, then `ECONNREFUSED` after 175 s.
- The model never made the Write, and the hook never ran. The classifier
  labelled it `PROTOCOL_DEVIATION`.
- The setup also lacked the `GIT_*` variables that scope §5.4 names for D-4.

**Fix.** #636 (merged as `7480b1f5`, SELFTEST OK 57/0) adds:
- `NO_PROXY`/`no_proxy=api.anthropic.com`, the only host Claude Code needs
  with API-key auth;
- a `GIT_CONFIG_COUNT`/`KEY_0`/`VALUE_0` `url.insteadOf` redirect to
  `blackhole.invalid`.

The expected outcome is unchanged. Run 2's script refused to start unless the
harness in use carried the fix.

**Result.** D-4 is 4/4 PASS in run 2. The run 1 D-4-Write-1 deviation is
published as recorded (`run1/D-4-Write-1/`). It is a harness defect, not a
Mneme result.

## 5. What this establishes

On Claude Code 2.1.303 headless, under `b0dc1a14`, with the fixture verified
`AUTHORIZED` at `51252310`:

- **P-2:** a violating edit under verified AUTHORIZED availability is still
  blocked as a decision violation, not an operational refusal.
- **P-7:** a pure deletion proceeds (the existing skip).
- **U-1 to U-3, verification unavailable:** a real Git-only network block
  never refuses on its own.
  - The compliant edit proceeds, with the §17 context delivered to the model.
  - A strict FAIL still blocks.
  - A missing memory does not trigger an availability refusal.
- **D-1 to D-5, disclosed limits, confirmed as limits:**
  - deleting the local declaration or `origin` turns protection off (D-1,
    D-2);
  - removing the hook bypasses it (D-5);
  - repository-local Git redirects (D-3) and settings-`env` proxies plus
    `GIT_*` (D-4) do **not**: the verifier ignored them and the missing
    memory was refused.
- **H-1 and H-2:** host behavior is recorded only. Missing hook command:
  blocked. Host timeout: proceeded.
- **E8:** the controls passed in both live runs.

Together with #620 (R-1), #622 (R-2), #632 (R-3 to R-7) and #629 (P-5), every
scope §5 row except P-6 now has headless live evidence under `b0dc1a14`. P-6

## 7. Findings for review

- **`github.com` during the Git-only block:** `github.com` appears in two U
  probes (U-1-Write-2, U-3-Edit-2) while `git-remote-https.exe` was blocked
  and the verifier reported `NETWORK`. That traffic cannot be the verifier's.
  This confirms the #632 finding: GitHub HTTPS from other host processes is
  routine, so a `github.com` server name never identifies the verifier by
  itself. Attribution rests on the wrapper half of E4.
- **Other hosts:** `api.anthropic.com` appears in nearly every capture,
  because it is Claude Code's API. `downloads.claude.ai`,
  `mcp-proxy.anthropic.com`, `alive.github.com`, `collector.github.com`,
  `avatars.githubusercontent.com` and `release-assets.githubusercontent.com`
  appear sporadically. No forbidden host (`blackhole.invalid`, `127.0.0.1`)
  appears in any capture, including D-3 and D-4.
- **H-1/H-2 asymmetry:** on this host, a hook that fails to launch blocks,
  but a hook that hangs past the timeout proceeds. This is recorded for the
  C3 closure discussion. It is not a Mneme claim.
