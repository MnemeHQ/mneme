## 6. What this does and does not show

Shown, in the isolated lab only, on 2026-10-26 (before GitHub's 2026-11-02
`pull_request_target` change):

- Under `closed`, an operational UNEVALUATED fails the genuine required check and
  GitHub refuses the head-pinned merge (L2); a compliant change merges (L1).
- Under explicit `open`, UNEVALUATED satisfies the required check and merges, and
  is reported as UNEVALUATED with a warning annotation, job summary and report
  label, never PASS (L3).
- Under `open`, a trusted-surface change is still refused (L4), and a strict
  violation is still refused (L5).
- The posture is administrator-controlled: switching it was an API operation on
  the repository variable, not a PR change.

Not shown:

- Behavior after 2026-11-02 or on any repository other than the lab. Core's
  production `mneme-check.yml` is unchanged and still an implicit `open` (ADR-033 §5).
- The live adapter pin-mismatch path, runner or bootstrap failure, and merge
  races. Head freshness and same-PR tampering are reused by reference from CI1
  (the head-fetch step is unchanged; trusted-surface refusal is re-proven by L4).
- Any ADR-029 "relevant enforcement observed" claim. That assessment belongs to
  Gate 4.
- The CI1 limits stay: administrative P7/P8 exposure (the ruleset disable in
  step 03 is an example of what an administrator can do), no governed decision
  update route, include-selector coverage, partial ADR-029 binding.

The lab's `tests/test_gate_workflow.py` and `gate/ci1_gate.py` still describe
the CI1 gate and were not updated; the workflow no longer runs `gate/ci1_gate.py`.
