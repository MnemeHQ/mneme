## Known MCP limitations (not release failures)

These are recorded explicitly so they are not mistaken for regressions in
the published package; they belong to later architecture work:

1. Accepted `project_memory` decisions are not yet automatically unified
   with MCP canonical reads (accepted decisions materialize through the
   human authority CLI; MCP canonical reads are sourced separately).
2. An already-running MCP process does not automatically refresh after
   an external accept/reject (server restart is required to pick up
   external authority actions).

## Outcome

- `v0.9.0` is published and validated from the published bytes — not a
  source checkout — for both the automated artifact smoke and the
  additional MCP/decision clean-install verification.
- Known MCP limitations above are pre-existing architectural boundaries,
  deferred to later work, not release failures.
