# v0.5.2 — Enforcement quality benchmark, phrase-sequence matcher fix, Codex CLI integration

**The legacy phrase-sequence matcher is fixed, the FPR benchmark suite ships, and Codex CLI joins the native integrations.**

A patch release with three independent deliverables that all share one theme: measurable, trustworthy enforcement.

```bash
pipx install "mneme-hq>=0.5.2"
```

---

## Fixed

### Phrase-sequence matching for legacy anti-patterns (ADR-017 amendment, #317)

The legacy matcher previously treated *any single term* from a descriptive phrase as the whole rule. A rule described as `open() without encoding=` would fire on `open`, `without`, `encoding`, or `=` in isolation — causing false positives on benign prose (e.g., ADR-003 content containing "governance", "open", "without").

The matcher now requires the full phrase sequence. The dogfood false-positive on site governance content is eliminated.

---

## Added

### Enforcement-quality benchmark suite with partitioned FPR reporting (charter #318, #319, #320)

New benchmark scenarios cover:
- Legacy anti-patterns (pre-typed rules)
- Typed literal rules (`FORBID_LITERAL`)
- Introduced-delta enforcement (ADR-018)

False-positive rates are tracked per rule class. The benchmark runner is gated by the Layer 1 freeze amendment and does not run in the standard CI `pytest` suite — it is a charter instrument, not a regression gate.

### Codex CLI enforcement integration (#321)

Native `PreToolUse` gate + `Stop` session-delta audit for Codex CLI. Reuses `mneme check` semantics: hook evaluates proposed tool calls against the project's ADRs, and the `Stop` hook audits the session's working-tree delta. Native integrations now cover: **Claude Code, Claude Agent SDK, Google Antigravity, Codex CLI**.

---

## Compatibility

- Existing `constraints` and `anti_patterns` retain their current matching and severity behavior. Memory files without `rules` continue to load unchanged.
- Existing scalar typed rules remain global. Selector fields are additive and the check JSON schema remains `mneme.check/v1` with additive fields.
- No retrieval, `DecisionRetriever`, or `ConflictDetector` semantics change.

---

## Scope and honest limits

- **Benchmark suite is not a CI gate.** It runs on demand (`python -m mneme.benchmark`) and is gated by the Layer 1 freeze charter. Do not treat it as a regression test.
- **Codex CLI validation is manual.** No automated end-to-end test runs in CI for Codex; the integration reuses the same `mneme check` path as Claude Code and is covered by the hook e2e tests.
- **ADR-021 (shell preflight + Stop session delta) is not yet imported.** Run `mneme adr import` after upgrade to activate it.
- **Pre-existing ADR hash mismatches** for ADR-001, 002, 004, 009, 010, 014, 017 are unrelated to this release — they reflect source-file edits since the last `mneme adr import`.

---

## Upgrading

No configuration changes. `mneme-hq >= 0.5.2` is required for the fixed phrase-sequence matcher and Codex CLI integration.
