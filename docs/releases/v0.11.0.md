# mneme-hq 0.11.0

**Decision governance semantics, a numeric rule type, opt-in fail-closed
availability, and enforcement-trust fixes.**

This release ships the ADR-031 decision governance semantics (DG1), the
`FORBID_NUMERIC_ABOVE` typed rule (ADR-034), opt-in fail-closed availability
for Claude Code direct writes (ADR-033), and several fixes to when an
enforcement result is trusted.

**This release contains behavior changes.** Read
[Behavior and compatibility changes](#behavior-and-compatibility-changes)
before upgrading.

## Behavior and compatibility changes

### 1. ADR `date` is no longer precedence authority (DG1P)

Two accepted ADRs in the same exact scope with the same priority used to be
resolved by the newer `date`. They are now an active-active contradiction
unless one explicitly `supersedes` the other or has a higher priority.

- `mneme adr import` reports the scope as a contradiction: dry-run exits 1,
  and `--apply` refuses unless `--approve-conflicts`, which skips that scope.
- Decisions already canonical in such a scope are never deactivated or
  rewritten by re-import.
- The Decision MCP `--adr-dir` view and `compile_adrs` raise
  `ADRPrecedenceError` for such a corpus.

**Upgrade:** add an explicit `supersedes` link, or give one ADR a higher
priority.

### 2. `mneme.decision-index/v2` memory is unreadable by 0.10.x and older

Decision applicability (DG1B1) and `FORBID_NUMERIC_ABOVE` rules are stored
only under `mneme.decision-index/v2`. Binaries at or below 0.10.x refuse a v2
document at load instead of misresolving it. **Upgrade every writer and
reader before any project gains v2 memory.**

### 3. Claude Code direct-write memory selection starts at the edited file (T-08 slice 1)

For `Edit`, `Write` and `MultiEdit`, memory discovery now starts at the
edited file's resolved directory instead of the session `cwd`. A session
rooted in a protected repository no longer applies that repository's rules
to edits in other repositories. If you relied on the session `cwd` to block
cross-repository edits, add a memory to the other repository. `MNEME_MEMORY`
still takes precedence when set.

### 4. Only coherent `mneme check` verdicts are trusted

The Claude Code hook, Agent SDK and LangChain consumers now trust a check
payload only when its mode, violation records, aggregate verdict and exit
code agree (for example, a PASS with exit 1 is no longer trusted). An
incoherent result fails open with a diagnostic that names the contradiction.

### 5. Relative tool paths resolve against the event `cwd`

The current-file snapshot used to compute an edit's introduced lines is now
read from the same resolved path that `mneme check` receives. Previously, a
relative path was read against the host process cwd, which could silently
skip a forbidden edit, produce a false PASS, or blame pre-existing
violations on an unrelated write. This affects the Claude Code, Agent SDK,
LangChain, Kiro, Antigravity and Hermes paths. Absolute paths behave as
before.

### 6. Mixed numeric results keep trusted violations actionable

When a check is incomplete only because numeric rules are unevaluated, the
Claude Code hook, the Agent SDK and LangChain keep a trusted violation
actionable (deny in strict mode) instead of failing open.

## Added

- **Opt-in fail-closed availability (ADR-033).** New
  `mneme availability status | authorize | revoke`. A repository opts in
  with `.mneme/availability.json`, which counts only when the live default
  branch of `origin` holds a reviewed authorization event for it. While the
  baseline is verified as authorized, the hook refuses a direct write that
  cannot be checked or trusted. Without a declaration, hook behavior is
  byte-identical. See `docs/integrations/claude-code.md`.
  - **Known limitation:** deleting the local declaration can silently
    disable opt-in fail-closed protection. When authorization cannot be
    verified (for example, a DNS failure), the edit proceeds and the hook
    emits a PreToolUse `additionalContext` notice. That notice is not
    evidence that a file changed and is not a check result.
- **`FORBID_NUMERIC_ABOVE` (ADR-034).** Declares an inclusive upper bound on
  a Python module-level symbol and/or a positional argument of direct
  calls. It supports complete-source auditing through
  `mneme check --source-file <file.py>`, and implements a separate
  `mneme check --proposed-new-file` evaluation path for G2-1 (below). Other
  incomplete inputs report it `UNEVALUATED`, never PASS. See
  `docs/integrations/adr-import.md`.
  - **Pre-write check for new-file `Write` (G2-1), no support claim.** A
    Claude Code `PreToolUse` `Write` to a verified-absent `.py` target in an
    existing directory is checked as complete proposed source through the
    `--proposed-new-file` path. That path has not passed independent
    validation, and its inclusion does **not** establish supported pre-write
    enforcement. Edits, existing-file writes, Bash, Stop, CI and the other
    integrations are not covered.
  - The response-text conflict detector reports numeric rules in a new
    `noncoverage` list; `ConflictDetector.detect()` raises
    `NumericRuleNoncoverageError` for decision sets containing them.
- **Decision governance library (DG1C, DG1D, DG1E, DG1B1).**
  `mneme.decision_governance` adds the effective-decision resolver and
  governance change resolution; `mneme check --json` adds canonical
  evidence identity; decisions can carry canonical applicability.
- **`mneme check --applicability-preview LABEL` (DG1F-C1a).** Opt-in,
  report-only, marked `NON-AUTHORITATIVE` on stderr. Stdout, JSON and exit
  codes are unchanged.
- **Additive `mneme.check/v1` fields** for numeric rules (per-rule matcher
  fields, violation details and a top-level `subject`). Payloads for checks
  without numeric rules are byte-identical.

## Fixed

- `FORBID_NUMERIC_ABOVE` matcher: `--input` without `--target-path` is never
  a clean numeric result (F-1); call sites resolve by lexical scope (D2);
  dynamic writes to the governed symbol (`globals()[...]`, `setattr`, star
  imports and similar) report `AMBIGUOUS_BINDING` instead of a clean PASS
  (S1).
- `mneme adr import` reports ADR parse and schema errors without a
  traceback and leaves canonical memory unchanged.
- `mneme decision-index migrate` names a lossless route when it refuses a
  free-text decision source.
- `mneme check` starts faster: modules used only by other subcommands are
  imported lazily.

## Unchanged

- Retrieval ranking and `DecisionRetriever`.
- `FORBID_LITERAL` and other existing typed-rule semantics.
- The `mneme.check/v1` schema identifier, `mneme.audit/v1` and the Decision
  MCP tools.
- The hook's subprocess transport, 10 s timeout and fail-open default.

## Upgrading

1. Upgrade every machine and CI job that reads or writes a project's memory
   to 0.11.0 before any of them writes `mneme.decision-index/v2` memory.
2. Run `mneme adr import` as a dry-run. If it reports a date-only
   contradiction, add a `supersedes` link or a priority before `--apply`.
3. If you relied on a session's working directory to block edits in another
   repository, add a memory to that repository.
