## 1. Three different kinds of input; none may be silently promoted

1. **Persisted decision authority**: `decision_index` in `.mneme/project_memory.json` is validated and projected by `MemoryStore.load`. A valid snapshot is a canonical representation, **not** proof of an independently approved revision or protection from local substitution. Without a canonical section, legacy `decisions[]` can still load; that is **not** C1b context provenance.
2. **Evaluation context**: `GovernanceContext.labels` contains opaque, project-local strings. `resolve_effective` evaluates their exact containment *after* lifecycle. The existing caller-supplied `--applicability-preview` labels are **NON-AUTHORITATIVE** and never reach enforcement.
3. **Retrieval, checked path and delivery context**: query, scope hints, file paths, tool payloads, runtime environment and repository location may help retrieval, ADR-020 *rule-path* selection, or transport; none authenticates applicability labels or upgrades proposals into authoritative decisions.

**Global finding:** source inspection did **not** locate the C1b trust mechanism required by the merged charter: review-gated persisted context declaration with an independently verifiable approved revision, unreviewed-substitution protection, controlled context selection, and blocking-seam safety. There is no approved enforcement-context label source in these consumers today. A fail-closed *parser* or *writer* is not proof that a downstream agent/action is prevented from proceeding.

## 3. Additional adapter and transport evidence (do not collapse into one “hook”)

- **Kiro**: `mneme/integrations/kiro/hook.py:_run_check` maps JSON verdict to Kiro exit codes, emits `UNEVALUATED` and returns 0 on degraded input/transport.
- **Codex CLI**: `mneme/integrations/codex_cli/gate.py` describes `DENY > FAIL_OPEN > WARN > PASS/SKIP` aggregation; `stop_audit.py` evaluates post-change file contents and permits continuation when observations are incomplete.
- **Claude Code / Agent SDK**: `mneme/integrations/claude_code/hook.py:parse_verdict/_run_check` and `mneme/integrations/agent_sdk/adapter.py:evaluate_mutation/pre_tool_use` deliberately fail open when the checker returns no trusted verdict.
- **Hermes**: `mneme/integrations/hermes/adapter.py:evaluate_tool_call` identifies `execute_code` and `process` as unevaluated surfaces; `terminal` and patch modes have their own coverage limits.
- **LangChain**: `mneme/integrations/langchain/adapter.py:evaluate_tool_call` only governs mapped file tools and delegates to Agent SDK. Unmapped tools are explicitly skipped.
- **Antigravity**: `mneme/integrations/antigravity/adapter.py:main` maps selected tool events through the check parser, with degraded outcomes non-blocking.
- **GitHub/CI consumers**: the C1 charter explicitly notes the blocking-seam risk. **Not yet exhaustively audited here**: which CI jobs invoke `mneme check`, their stdout/schema/exit interpretation, and whether a malformed or missing verdict blocks the specific protected action. Do not infer this from a green repository CI workflow or the self-check's warn-mode status.

## 4. Cross-cutting findings and unresolved evidence

| ID | Verified observation | Missing evidence or decision (not authorization) |
| --- | --- | --- |
| T1 — Canonical source | Canonical index can be validated at load and projected without duplicated authority; C1a preview reads the *same* snapshot. | Independently verifiable approved **revision identity**, protection against substitution between review/execution, and approved canonical context declaration are **not** established. |
| T2 — Context selection | CLI, hooks, MCP and adapters accept caller/agent/task inputs; `GovernanceContext.labels` evaluates exact supplied strings. | Who controls a context **selector**, how a reviewed declaration is bound to the exact execution, and how a caller is prevented from arbitrarily choosing an excluding context. |
| T3 — Failure boundary | CLI can indicate operational failure; adapter/hooks frequently return non-blocking transport outcomes on missing/malformed results. | Independent, per-integration **blocking-seam** tests for malformed JSON, missing memory, timeout, path `UNKNOWN`, invalid canonical memory, and abort/continue semantics. |
| T4 — Scope of enforcement | CLI uses full scored corpus with ADR-017 retrieval-gated legacy checks and corpus-wide typed literals; Pipeline ConflictDetector uses injected top-scoring decisions. | Any future authoritative filter must run **before** top-K, preserve global typed rules and ADR-020 path selectors, and not rewrite detection/retrieval as an authority model. |
| T5 — Derived views | Protection eligibility and Audit/readiness have their own lifecycle-active checks and frozen reporting semantics. | Surface-by-surface impact analysis and parity evidence before *any* convergence; no assumption that a successful CLI change propagates to these views. |
| T6 — Provenance vs claims | MCP read APIs separate canonical from proposed records; public Audit does not upgrade untrusted evidence claims to verified. | A reviewed trust root, version binding and replayable proof for any future C1b context; proposal or Audit observations alone cannot supply it. |
